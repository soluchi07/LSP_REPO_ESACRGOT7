# Template Method Design Explanation

The Template Method pattern is applied through the abstract `Report` class, which defines `generateReport()` as a `final` method that enforces the fixed workflow: `loadData()` → `formatHeader()` → `formatBody()` → `formatFooter()`. The four steps are declared `abstract` in `Report`, forcing each concrete subclass — `StudentReport` and `CourseReport` — to supply its own implementations while the overall sequence remains under the control of the superclass. Because `generateReport()` is final, no subclass can reorder or skip any step. The driver stores both concrete reports in a `List<Report>` and calls `generateReport()` on each, demonstrating polymorphism: the caller never needs to know which specific subclass it holds, yet each report produces its own correct output.
